# 误差分析（T10）：验证集 170 张

> 编制：宁湘涵 · 2026-11-20
> 脚本：`insulator_yolo/error_analysis.py`；产物：`insulator_yolo/runs/error_analysis/`。
> 分析对象：本机训练的 320/20 轮基线（`runs/detect/ning_baseline-2/weights/best.pt`）。

## 一、结论先行

**验证集 50 个缺陷框全部漏检（100%），误检 0 个，定位偏差 0 个。**

这个结果不是"阈值太高"造成的：把置信度阈值压到 0.01、并把推理分辨率提到 640 重新跑，
**仍然没有任何 `defect` 预测框**。也就是说模型的缺陷分支根本没有输出。

| 指标（conf=0.05） | 数值 |
|---|---|
| 验证集图像 | 170（缺陷 50 / 正常 120）|
| GT `defect` 框 | 50 |
| 预测 `defect` 框 | **0** |
| 图级检出率 | **0.0%** |
| 漏检 FN | **50** |
| 误检 FP | 0 |
| 定位偏差（IoU 0.1–0.5） | 0 |

## 二、为什么 T10 的验收线暂时无法满足

计划书对 T10 的要求是"**漏检、误检各不少于 15 例并给出归因**"。当前模型下：

- 漏检：50 例，**数量够，但全部是同一类原因**（缺陷类未学习），归因写不出多样性；
- 误检：**0 例**，因为模型从不输出缺陷框——没有样本可分析。

所以 T10 的正式分析**必须等一个能检出缺陷的模型**（B/C/D 组任一）。本文件先把"当前模型的误差结构"
和"为什么是这个结构"记录下来，等模型具备检出能力后按同一脚本重跑即可补齐。

## 三、根因分析（三条证据指向同一结论）

| 证据 | 数据 | 说明 |
|---|---|---|
| 训练集上也检不出 | train split `defect AP50 = 0.0037` | 不是泛化问题，是**拟合失败** |
| 与推理分辨率无关 | 320 与 640 推理均为 0 框 | 不是后处理/尺度失配 |
| 目标过小 | 缺陷框中位边长 55 px（占图宽 4.8%），320 输入下约 15 px | 低于 P3 头有效感受野 |

`insulator` 类则正常：验证集 AP50 = 0.888、训练集 0.892，说明数据、标签、训练链路本身没有坏，
问题定位在**小目标 + 极端不均衡**的缺陷类上。

## 四、对照实验（验证"是否只是训练不够"）

| 配置 | 轮次 | val `insulator` AP50 | val `defect` AP50 | train `defect` AP50 |
|---|---|---|---|---|
| 320 / batch8 | 20 | 0.8876 | 0.0014 | 0.0037 |
| 640 / batch8 | 6 | 0.5346 | 0.0000 | 0.0000 |

640 组只跑了 6 轮（CPU 约 5.4 min/轮），`insulator` 都还没收敛（0.53 对 0.89），
因此**不能据此判定 640 无效**，只能说"6 轮之内缺陷类仍未起来"。要下结论需要 20~30 轮，
按计划书 C 组的安排过夜跑。

## 五、对后续工作的建议

1. **优先跑 D 组**（Focal + 类权重 2.0）：缺陷类的问题是"正样本梯度被背景淹没"，
   损失层加权是最直接的干预，且只需 2.3 h；
2. **B 组过采样**（`prepare_dataset.py --defect-repeat 2`）可与 D 叠加；
3. C 组（640）建议直接配 30 轮过夜，不要用 6 轮的结论；
4. 一旦某组 `defect AP50 > 0.05`，立刻用本脚本重跑：
   ```powershell
   python error_analysis.py --weights <best.pt> --conf 0.05 --imgsz 640
   ```
   届时 `runs/error_analysis/fn.csv`、`fp.csv`、`loc.csv` 会有内容，`cases/` 会导出带框样例图，
   逐张写归因即可（预计 4 h 内完成 T10）。
