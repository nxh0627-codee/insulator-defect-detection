# 复现记录：基线 0.871 在当前环境下的复现结果（2026-11-20）

> 结论先行：**用仓库现有代码在本机复现不出 `mAP50 = 0.871`，实测 0.4445；差距几乎全部落在 `defect` 类（本机 defect AP50 ≈ 0）。**
> 这不是"训练不够久"的问题——`defect` 的召回从第 1 轮起就是 0，20 轮后仍是 0。

## 一、对比

| 指标 | 仓库记录（8 轮 / batch16 / 320） | 本次复现（20 轮 / batch8 / 320） |
|---|---|---|
| mAP@0.5 | **0.871** | 0.4445 |
| mAP@0.5:0.95 | 0.547 | 0.3053 |
| P / R | 0.806 / 0.816 | 0.9615 / 0.4164 |
| `insulator` AP50 | 0.963 | **0.888**（接近） |
| `defect` AP50 | **0.779** | **0.00145** |
| `defect` Recall | 0.680 | **0.000** |

`insulator` 基本追上了（0.888 vs 0.963，差 7.5 个点，尚可用"训练轮次不同"解释）；
但 `defect` 是**量级差异**：0.779 对 0.00145，召回 0.68 对 0.00。

## 二、证据链

1. 第 1 轮验证：仓库记录 `P=0.933 R=0.388 mAP50=0.431`；本次 `P=0.0 R=0.0 mAP50=0.0`；
2. 逐轮 `results.csv` 里 `defect` 从未出现在有效预测中——用 `error_analysis.py` 在 `conf=0.01`（极低阈值）下跑验证集 170 张，
   **`pred_defect_boxes = 0`**，50 个 GT 缺陷框全部漏检；
3. 把推理分辨率提到 640（权重不变）仍是 0 个缺陷预测，说明不是"后处理阈值"问题，而是分类分支压根没学出来。

## 三、可能原因（按可能性排序）

| 假设 | 依据 | 验证方式 |
|---|---|---|
| **训练分辨率不足** | 缺陷框边长中位 55 px（占图宽 4.8%），320 输入下只剩 ~15 px，低于 P3 头有效感受野 | 正在跑 640 实验（6 轮）对比 defect AP50 |
| 梯度累积导致有效步数少 | `nbs=64`、batch 8 → 每 8 个 microbatch 才更新一次，每轮约 10 次参数更新 | batch 16 实验（卡住已终止），可改 `nbs=8` 再试 |
| 历史 run 的配置与 `args.yaml` 不符 | 仓库 `results.csv` 第 1 轮就有 0.43 mAP50，对 COCO 预训练模型也偏高；且该 run 耗时 213 s/轮，本机 58 s/轮 | 需要原始环境信息（ultralytics / torch 版本、是否 GPU）|
| 标签或划分不一致 | 本机用 `prepare_dataset.py` 重新生成，678/170 与记录一致；框数 1321 + 248 一致 | 已核对，排除 |

## 四、对团队的影响（重要）

1. **报告里的 0.871 / 0.779 不能直接写**，除非能证明可复现——答辩被要求现场复现会很尴尬；
2. 若 640 实验能让 `defect` 学起来，则"缺陷是小目标、必须提高分辨率"这个结论本身就有实验支撑，反而是个亮点；
3. 建议戴海青核对最初那次训练的完整配置（是否 640、是否 GPU、ultralytics 具体版本），把 `args.yaml` 补全到可复现的程度。

## 五、复现命令（本机）

```powershell
cd insulator_yolo
python train.py --epochs 20 --imgsz 320 --batch 8 --workers 0 --patience 10 --cache --name ning_baseline
python error_analysis.py --weights runs/detect/ning_baseline-2/weights/best.pt --conf 0.01 --imgsz 640
```

环境：ultralytics 8.4.215 / torch 2.7.1+cpu / Python 3.11.17 / i7-13650HX（20 线程，无 GPU）。
## 六、补充证据：缺陷类是"根本没学会"，不是泛化不好

把同一个 320 权重拿到**训练集本身**上评估（678 张，理论上应接近满分）：

| split | mAP50 | mAP50-95 | insulator AP50 | defect AP50 |
|---|---|---|---|---|
| train（678 张） | 0.4480 | 0.3080 | **0.8923** | **0.0037** |
| val（170 张） | 0.4445 | 0.3053 | 0.8880 | **0.00145** |

训练集上 `insulator` 能到 0.89、`defect` 只有 0.0037 —— **模型对缺陷类的拟合在训练集上就是零**。
这排除了"过拟合/泛化差"的解释，指向三个结构性原因：

1. **目标太小**：缺陷框中位边长 55 px，320 输入下约 15 px，P3 头（stride 8）只有不到 2 个格子；
2. **正样本太少**：248 个 defect 框 vs 1321 个 insulator 框 + 每张图上千个背景锚点；
3. **TAL 分配偏向大目标**：缺陷框几乎总被更大的 `insulator` 框覆盖，对齐度量里 insulator 占优。

对应的三条修复路径恰好就是消融实验的 B/C/D 组：过采样（B）、640 分辨率（C）、Focal + 类权重（D）。
